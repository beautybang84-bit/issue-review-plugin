# 세무 이슈 검토 파이프라인

모든 소통은 한국어로 한다. $ARGUMENTS 가 검토할 이슈다. 비어 있으면 이슈 내용을 물어본다.

## 0. 설정 읽기

`~/.claude/issue-review-config.json`을 Read로 읽는다. 파일이 없으면 선택 항목(gpt_review, casenote)은 끈 것으로 보고 진행하고, 마지막에 "`/이슈검토설정`으로 켤 수 있다"고 한 줄 안내한다. 형식은 `/회계이슈` 스킬 0단계와 같다.

회계처리가 걸린 혼합 이슈면 세무 부분을 이 파이프라인으로 보고, 회계 부분은 `/회계이슈`로 따로 보라고 안내한다.

## 1. 병렬 조사 — 하나의 메시지에서 동시에

1. `nts-tax-search` agent — 유권해석(질의회신·서면질의·사전답변)·조세심판례·조세판례 【본조사】
2. `korean-law-search` agent — 법령 조문 원문(행위시법 포함)·법원판례 【본조사】
3. `web-search` agent — 개정 동향·실무 해설 【참고 전용 — 본문 논거로 쓰지 않음】
4. **TaxDoctor 누락 점검 (agent 없이 메인에서 직접)** — `mcp__taxdoctor__search_tax`를 `detail: "list"`로 1회. `search_intents`는 law·ruling·tribunal 위주.
   - 용도는 본조사가 놓친 근거 찾기뿐이다. 쟁점에 맞는 것만 골라 둔다.
   - 본조사에 없는 유효 후보는 `nts-tax-search`로 원문을 확인한 뒤에만 논거에 넣는다.
   - 본조사보다 최근 심판례는 특히 확인한다.

결론과 논거는 본조사 2종에서만 만든다. 웹 결과는 말미 「추가 참고의견」에만 둔다.

## 2. 취합과 상충 판정

상충하면 상충 지점을 명시하고 다음 순서로 따른다: 국세법령정보시스템 > 국가법령정보센터 > TaxDoctor > CaseNote. 웹은 우선순위 대상이 아니다.
과거 사업연도 쟁점은 행위시 조문을 기준으로 한다 (TaxDoctor `get_article`에 `as_of`, 부칙·적용례는 `get_amendments`).

## 3. 인용 검증 (매번 자동)

**사전 점검 — `mcp__taxdoctor__verify_citations` (메인에서 직접):** 취합본의 문서번호·사건번호·조문을 넣어 번호 존재부터 거른다.
- `not_found`는 "TaxDoctor 미발견" 메모를 달아 citation-verify에 우선 점검시킨다 (미수록일 수 있으니 여기서 버리지 않는다).
- 옛 형식 번호(`서면2팀-1021`, `법인46012-` 등)는 결과에서 조용히 빠지므로, 입력 건수와 검사 건수를 대조해 빠진 번호는 citation-verify 결과로만 판정한다.
- `found`는 번호 존재일 뿐 취지 일치가 아니다.

이어서 `citation-verify` agent를 사용자 요청 없이 매번 실행해, 인용 전수를 원문 대조(존재 + 판시 취지 일치)한다.

**"확인" 외 판정이 나오면 재조사 루프:**
1. 확인불가·번호오류 → `nts-tax-search`로 1회 재조사 (번호 재조회 + 쟁점 키워드 재검색)
2. 불일치(존재하나 취지 왜곡) → 그 인용은 버리고 취지에 맞는 다른 근거를 재탐색
3. 그래도 안 되고 `casenote.enabled`가 true면 → `casenote-search` agent (순차 1개씩만, 병렬 금지)
4. 못 찾으면 혼자 톤다운하지 말고 사용자에게 넘긴다: 어떤 인용이 왜 확인 안 되는지, 출처를 아는지 질문, 직접 확인할 검색 경로(taxlaw.nts.go.kr 키워드·문서번호 형식) 제시
5. 미확정 논거는 [미확정]으로 표시하고 확인된 부분부터 전달한다

## 4. GPT 교차검토 (선택)

`gpt_review.enabled`가 true면 확정본(결론·검토내용·근거목록)을 `gpt-review` agent에 넘긴다.
- 타당한 지적은 반영하고, 반영하지 않은 지적은 이유와 함께 「상충·한계」에 적는다.
- GPT가 새로 꺼낸 판례·예규는 [미검증] — citation-verify로 확인한 뒤에만 쓴다.
- 실패하면 멈추지 말고 「상충·한계」에 "GPT 교차검토 미실시(사유)"로 적는다.

## 5. 보고 형식

```
## 결론
(핵심 답변 2~4문장. 조건부면 조건 명시)

## 검토 내용
(논거 전개. 근거마다 문서번호·생산기관·회신일자 / 법령명·조문번호 / 사건번호·선고일자)

## 근거 목록
| # | 출처 | 핵심 내용 | 검증(citation-verify 판정) |

## 상충·한계
(상충 지점, [미확정] 인용, 꺼져 있던 선택 항목, 반영하지 않은 GPT 지적)

## GPT 교차검토 (켠 경우)

## 추가 참고의견 (웹)
(한두 줄. 웹 결과는 여기에만)
```

사용자가 저장을 요청하면 `save_root`(비어 있으면 사용자에게 경로 확인) 아래 해당 거래처·프로젝트 폴더에 `.md`로 저장한다.

## 6. 주의

- nts-tax 또는 korean-law MCP가 연결되어 있지 않으면 해당 agent가 웹 검색 대체 경로를 쓴다. 이 경우 「상충·한계」에 "MCP 미연결로 웹 경로 사용"을 적고, README의 설치 안내를 한 줄 알려 준다.
- agent가 확인하지 못했다고 한 내용을 사전지식으로 메우지 않는다.
- 검토 결과는 실무 참고용이며, 최종 판단은 담당 세무사·회계사가 한다.
