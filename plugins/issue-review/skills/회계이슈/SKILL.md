# 회계 이슈 검토 파이프라인

모든 소통은 한국어로 한다. $ARGUMENTS 가 검토할 이슈다. 비어 있으면 이슈 내용을 물어본다.

## 0. 설정 읽기

`~/.claude/issue-review-config.json`을 Read로 읽는다. 파일이 없으면 선택 항목은 모두 끈 것으로 보고 진행하되, 마지막에 "`/이슈검토설정`으로 NotebookLM·GPT 교차검토를 켤 수 있다"고 한 줄 안내한다.

```json
{
  "notebooklm": { "enabled": false, "practice_notebook": "", "standards_notebook": "" },
  "gpt_review": { "enabled": false },
  "casenote":   { "enabled": false },
  "save_root":  ""
}
```

## 1. 적용 기준 확인

이슈가 K-IFRS인지 일반기업회계기준(K-GAAP)인지 먼저 가린다. 알 수 없으면 두 기준을 구분해 조사하도록 각 agent에 지시한다 (묻지 않고 진행).
세무 효과가 걸린 혼합 이슈면 이 파이프라인을 돌린 뒤 세무 부분은 `/세무이슈`로 따로 보라고 안내한다.

## 2. 병렬 조사 — 하나의 메시지에서 동시에

**기본 (항상)**
1. `kasb-search` agent — 회계기준원: 기준서 원문, 질의회신, 회계기준적용의견서, 신속처리질의
2. `web-search` agent — 감독동향·간행물·실무 해설 (참고 수준)
3. **회계위키 MCP (agent 없이 메인에서 직접)** — `mcp__accountingwiki__find_evidence`를 먼저 1회 호출 (도메인: K-IFRS→ifrs, 일반기업회계기준→kgaap, 감사→audit, 내부회계→icfr). 결과가 약하면 기준서 용어로 바꿔 `search` → `fetch`. 필요하면 `get_paragraphs`(문단 원문), `get_related`·`list_audit_cases`(관련 질의회신·감리지적사례). 인용할 때는 응답의 출처 URL을 그대로 쓴다.

**선택 (설정에서 켠 경우만)**
4. `notebooklm-search` agent — `notebooklm.enabled`가 true이고 `practice_notebook`이 있으면, 프롬프트에 "노트북 식별자: {practice_notebook}"를 넣어 실무자료 노트북 조회
5. `notebooklm-search` agent 한 번 더 — `standards_notebook`이 있으면 "노트북 식별자: {standards_notebook}, 기준서 원문·문단번호 위주"로 조회

**DART 공시 사례는 기본 조합에서 뺀다.** 사용자가 공시 사례를 명시적으로 원할 때만 웹 검색으로 보완한다.

## 3. 취합과 상충 판정

agent 보고와 회계위키 결과를 하나의 결론으로 묶는다. 상충하면 **상충 지점을 명시**하고 출처 유형 기준으로 판단한다.

1. 기준서 원문(K-IFRS·일반기업회계기준 문단) — 어느 경로에서 나왔든 최상위
2. 질의회신·적용의견서·감리지적사례 등 실무 해석
3. 웹, 회계위키 자체 실무해설(사례·해설 글, "공식 해석 아님") — 참고

회계위키 문단에 '기준서 상태' 알림(대체됨·시행 전)이 붙으면 현행 요건과 구분해 적는다.

## 4. 인용 점검 (매번)

취합 초안을 `mcp__accountingwiki__check_citations`에 넣어 기준서 문단번호·질의회신 번호가 실제로 있는지, 인용문이 원문과 같은지 확인한다. 문구 하나만 볼 때는 `verify_quote`.
- 없는 번호·불일치 인용은 고치거나 뺀다. 회계위키 미수록일 수 있는 것은 kasb-search 결과로 판정한다.
- 결과를 근거 목록 「검증」 열에 적는다.

## 5. GPT 교차검토 (선택)

`gpt_review.enabled`가 true이고, 결과가 거래처 회신·의견서·검토조서로 나가는 경우에만 확정본을 `gpt-review` agent에 넘긴다.
- 타당한 지적은 반영하고, 반영하지 않은 지적은 이유와 함께 「상충·한계」에 적는다.
- GPT가 새로 꺼낸 근거는 [미검증] — 회계위키·kasb-search로 확인한 뒤에만 쓴다.
- 실패(로그인·잔액·타임아웃)하면 멈추지 말고 「상충·한계」에 "GPT 교차검토 미실시(사유)"로 적는다.

## 6. 보고 형식

```
## 결론
(핵심 답변 2~4문장. 적용 기준 명시, 조건부면 조건 명시)

## 검토 내용
(논거 전개. 근거마다 기준서명·문단번호 / 질의회신 번호·회신일자 / 출처 URL)

## 근거 목록
| # | 출처 | 핵심 내용 | 출처 유형 | 검증 |

## 상충·한계
(상충 지점과 판단 근거, 확인 못 한 부분, 꺼져 있던 선택 항목, 반영하지 않은 GPT 지적)

## 추가 참고의견 (웹)
```

사용자가 저장을 요청하면 `save_root`(비어 있으면 사용자에게 경로 확인) 아래 해당 거래처·프로젝트 폴더에 `.md`로 저장한다.

## 7. 주의

- NotebookLM agent가 인증 오류를 보고하면 "`! nlm login` 재실행"을 안내하고, 나머지 결과로 먼저 취합한 뒤 한계에 적는다.
- 회계위키 MCP가 연결 안 되어 있거나 오류면 그 단계를 건너뛰고 「상충·한계」에 "회계위키 미조회(사유)"로 적는다.
- agent가 확인하지 못했다고 한 내용을 사전지식으로 메우지 않는다.
- 회계위키·각 출처는 실무 참고용이며, 최종 판단은 기준서 원문과 담당 회계사가 한다.
